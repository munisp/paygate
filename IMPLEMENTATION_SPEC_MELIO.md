# IMPLEMENTATION SPEC — Melio-Inspired AP/AR Suite (P0–P2)

Source: /mnt/agents/output/melio-paygate-gap-analysis.md. Recon: two agent digests (module map + middleware map).
Binding conventions (round-4): `withIdempotency` (server/idempotency.ts:86) on ALL money mutations with REQUIRED `idempotencyKey: z.string().min(8).max(128)`; merchant scoping via `resolveMerchantId(ctx.user.openId)` / `requireMerchant(userId)` (server/db.ts:3257) — never trust client merchantId; admin gates via DB re-check `requirePlatformAdmin`; `pbacProcedure('permission')` for privileged ops; guarded atomic updates (`UPDATE ... WHERE id=? AND status=? RETURNING`); `auditLog()` after mutations; bridge strict helpers (`bridgeCallStrict`) for money-path middleware, `safe()` for dashboards; `demoOrFail` for any simulation; money as `bigint('*_kobo',{mode:'number'})`; no mocks/placeholders on production paths.

## Canonical decisions (apply to ALL features)

D1. New routers live in NEW files under server/routers/ (ap*.ts / ar*.ts), exported as `export const <name>Router = router({...})`. Registration into server/routers.ts appRouter is done CENTRALLY by the orchestrator (agents must NOT edit server/routers.ts) to avoid 11-way merge conflicts on FUSE.
D2. All new tables are added by ONE schema wave (agent S0) into drizzle/schema.ts + migrations 0088–0091 + drizzle/meta/_journal.json. Feature agents import tables from schema; they do NOT add tables.
D3. Tests: each feature agent ships a vitest unit test `<router>.test.ts` next to the router, following server/routers/hostedCheckout.test.ts mocking pattern (vi.mock drizzle/schema + server/db chainable mocks). Pure internals exported as `__<name>Internals` where useful.
D4. Service calls: python/rust via direct fetch with `X-Internal-Key: env.internalApiKey` + `AbortSignal.timeout` (canonical: server/routers.ts:4270–4286); middleware via bridge helpers added to server/middlewareBridge.ts (money = strict, dashboards = safe). New env vars registered in server/_core/env.ts by the schema agent: ACCOUNTING_SYNC_URL, BILL_OCR_URL (defaults to kyc-ocr), ART_REASONING_URL.
D5. Events: publish domain events via server/kafkaClient.ts topics (`paygate.ap.bills`, `paygate.ap.payments`, `paygate.ar.invoices`, `paygate.accounting.sync`) and fluvioClient where streaming UI matters (`notification-stream`). Non-fatal (log + continue), EXCEPT ledger writes which stay bridge-strict.
D6. TigerBeetle: money movement reuses existing bridge strict helpers (wallet debit/credit, payout). New AP disbursements ride the EXISTING payout execution path (payouts.create → initiatePayoutApproval → Temporal) — no new ledger primitive.
D7. Vendor model: extend existing `vendors` table (schema.ts:7195) — add columns tin, bankCode, accountNumber, accountName, defaultPaymentTerms, creditBalanceKobo, openBalanceKobo via migration (ALTER TABLE), NOT a parallel table.
D8. AI_INSIGHTS port inconsistency: new code uses env var only, no hardcoded ports.

## Feature specs

### P0-a Vendor bill payment — server/routers/apBillPay.ts (`apBillPayRouter`)
Procedures: createBill (manual, withIdempotency), listBills (filters status/vendor/due), getBill (with line items + payments), updateBill (draft only, guarded status), voidBill (guarded), approveBill (P1-a rules; until rules exist default single-approval by merchant admin via pbacProcedure('approve_payout') + maker≠checker), payBill ({billId, fundingMethod: wallet|card|bank_transfer, idempotencyKey}) → validates ownership + status approved|partially_paid + remaining = total - amount_paid - vendor credit applied; computes fee (card 2.9% passed-through OR absorbed per P1-c setting; wallet/bank flat); wallet path = atomic guarded balance decrement (copy server/routers.ts:9754 pattern) then creates payouts row via existing createPayout helper + initiatePayoutApproval (strict); card path = Stripe PaymentIntent via server/stripe.ts createPaymentIntent (metadata {type:'ap_bill_funding', bill_id}) → on verify (payBillConfirm with paymentIntentId, canonical stripe:pi_ dedup) completes payout; applyVendorCredit (atomic on vendor_credits.remaining_kobo). Every state change → Kafka paygate.ap.bills + auditLog. Status transitions via guarded UPDATE...WHERE status IN (...) RETURNING (copy ecommerce.ts TOCTOU fix pattern).
### P0-b AP bill inbox + OCR — server/routers/apBillInbox.ts (`apBillInboxRouter`) + python-services/kyc-ocr extension
TS: uploadBillDocument (base64 → storagePut per wave122:342 pattern → create ap_bills row source=upload status=pending_extraction → trigger extraction), getExtractionStatus, confirmExtractedBill (human-in-loop: writes extracted fields onto bill, status extracted→draft-approved flow), listInbox. Email ingress: NEW python service python-services/bill-inbox/main.py (FastAPI, X-Internal-Key middleware copy kyc-ocr:571): POST /ingress/sendgrid (Inbound-Parse webhook: verify signature token env BILL_INBOX_TOKEN, save attachments to S3 via presigned flow callback to TS internal endpoint), GET /health. kyc-ocr extension: add doc_type 'supplier_invoice' + 'receipt' to DocType enum and extraction prompt fields {vendor_name, tin, bill_number, due_date, currency, line_items[], subtotal, tax, total} returning structured JSON; publish result to Kafka KYCExtractionResult topic (existing :531). TS extraction caller: new fetch to kyc-ocr /extract with doc_type supplier_invoice (env.kycOcrUrl, X-Internal-Key, 60s) — copy routers.ts:4257 pattern; parse into ap_bills.extracted_data + line items.
### P0-c B2B Pay-Over-Time — server/routers/apPayOverTime.ts (`apPayOverTimeRouter`)
getOffers (billId → calls credit-scoring `${env.creditScoringUrl}/score/merchant/${merchantId}` → terms: net30/3/6/12 installments from rate card, amortization copied from emi-service amortize), createPlan (withIdempotency; creates bnpl_plans + bnpl_loans rows linked to bill via new columns? NO — link via ap_payments.funding_method='pay_over_time' + plan_id in metadata jsonb on ap_payments), initiatePlan → pays vendor NOW in full through P0-a payBill internal path (payout), merchant owes plan; schedule in bnpl_repayment_schedules; repayInstallment reuses existing BNPL repayment sweep (cronJobs.ts:353). Wire emi-service LIVE: env EMI_SERVICE_URL, direct fetch POST /emi/plans/create + /emi/initiate as plan-record sidecall (non-fatal), replacing health-check-only status. Gating: payBill accepts fundingMethod 'pay_over_time' only when plan initiated atomically (create plan + payout in db.transaction; rollback on payout failure).
### P0-d Nigerian compliance pack — server/routers/taxCompliance.ts (`taxComplianceRouter`) + python tax-engine extension
TS: validateVendorTin ({vendorId}) → reads vendors.tin → calls tax-engine new endpoint POST /tin/validate (JTB/FIRS TIN format + checksum validation; external lookup behind env TIN_LOOKUP_URL, fail-closed 'unverified' when unconfigured — NO fabricated success) → upsert tin_validations + set vendors.is_wht_applicable per rules (companies 10% services/5% goods default rates from tax-engine GET /rates); computeBillWht internal helper (called by P0-a createBill/payBill: when vendor.is_wht_applicable and no exemption, wht = rate × subtotal, vendor receives net, wht_kobo recorded; inserts tax_withholding_records row with bill_id+vendor_id); listWhtRecords (merchant-scoped — replaces admin-only taxRouter for merchants' own records), generateWhtRemittance (period → aggregate unremitted records → wht_remittances + tax-engine POST /remittance via bridgeGet pattern tier6to8Router.ts:983), markRemitted (admin). taxFiling: extend existing taxFilingRouter usage — no change needed beyond linking. Python tax-engine: add /tin/validate + rate table for WHT types (services/goods/dividends/rent/commission + thresholds ₦... documented in code), keep X-Internal-Key.
### P0-e Accounting sync (QBO + Xero + Odoo) — server/routers/accountingSync.ts (`accountingSyncRouter`) + python-services/accounting-sync/main.py
Python (FastAPI, X-Internal-Key): POST /{provider}/oauth/url (build consent URL; client creds from env QBO_CLIENT_ID/SECRET, XERO_CLIENT_ID/SECRET, ODOO_CLIENT_ID/SECRET + ODOO_BASE_URL per connection), POST /{provider}/oauth/exchange (code→tokens, returns encrypted blob to TS for storage — encryption via env ACCOUNTING_TOKEN_KEY AES-GCM), POST /{provider}/refresh, POST /{provider}/push (entity=bill|invoice|payment, payload normalized), POST /{provider}/pull (cursor-based), GET /health. Provider adapters: quickbooks.py (v3 API minorversion, realmId base URL), xero.py (OAuth2 + tenantId header), odoo.py (OAuth2 where available else API-key/password auth via /web/session/authenticate + jsonrpc /jsonrpc model account.move methods create/write/read; map bill=in_invoice, invoice=out_invoice). NO MOCK ADAPTERS: if provider creds env absent → endpoints return 503 provider_not_configured. TS: connect (returns consent URL), handleCallback (stores accounting_connections, tokens encrypted), disconnect, listConnections, syncNow ({connectionId, direction, entity}) → withIdempotency → creates accounting_sync_runs → calls python push/pull → upserts accounting_entity_map; pull creates ap_bills (source=accounting_sync, idempotency via entity_map) and AR invoices; push sends approved/paid bills + paid invoices. Token refresh with row lock (UPDATE ... WHERE id AND token_expires_at RETURNING). Reconciliation: after sync, optional POST to reconciliation-engine /reconcile (existing :345). Kafka paygate.accounting.sync events.
