# PayGate mTLS Certificates

This directory holds TLS certificates for mutual TLS (mTLS) between APISIX and
the PayGate app server.

> this repository and must be considered **compromised**. They have been
> removed from the tree. **Rotate all certificates issued from that CA
> immediately**: generate a fresh CA + keypairs (see below) and redeploy to
> every gateway/server that trusts the old `ca.crt`.

## Policy

- Private keys (`*.key`) are **never committed** — enforced via `.gitignore`
  (`*.key`, `infra/certs/*.key`).
- Only public material (`*.crt`) lives in git.
- In production use a real PKI (HashiCorp Vault, cert-manager, AWS ACM)
  instead of these self-signed certificates.

## Generating certificates

Run the generation script (wrapper around the openssl commands below):

```bash
scripts/gen-certs.sh           # default 3650-day validity
scripts/gen-certs.sh 825       # custom validity (days)
```

Equivalent manual openssl commands:

```bash
cd infra/certs

# 1. Root CA
openssl genrsa -out ca.key 4096
openssl req -new -x509 -days 3650 -key ca.key -out ca.crt \
  -subj "/CN=PayGate Internal CA/O=PayGate Financial Services/C=NG"

# 2. Server certificate
openssl genrsa -out server.key 4096
openssl req -new -key server.key -out server.csr \
  -subj "/CN=paygate-app-server/O=PayGate Financial Services/C=NG"
openssl x509 -req -days 3650 -in server.csr -CA ca.crt -CAkey ca.key \
  -CAcreateserial -out server.crt

# 3. Client certificate (APISIX gateway)
openssl genrsa -out client.key 4096
openssl req -new -key client.key -out client.csr \
  -subj "/CN=apisix-gateway/O=PayGate Financial Services/C=NG"
openssl x509 -req -days 3650 -in client.csr -CA ca.crt -CAkey ca.key \
  -CAcreateserial -out client.crt
```

See also `generate-certs.sh` / `generate-mtls-certs.sh` in this directory.

## Files

| File | Description | Committed? |
|------|-------------|------------|
| `ca.crt` | Root CA certificate | yes |
| `ca.key` | Root CA private key | **NO — generate locally** |
| `server.crt` | App server certificate | yes |
| `server.key` | App server private key | **NO — generate locally** |
| `client.crt` | APISIX gateway client certificate | yes |
| `client.key` | APISIX client private key | **NO — generate locally** |
| `*.csr` | Signing requests (regenerable) | no |

## Usage

### APISIX upstream mTLS config
```yaml
upstream:
  tls:
    client_cert: |
      <contents of client.crt>
    client_key: |
      <contents of client.key>
    verify: true
    trusted_ca_cert: |
      <contents of ca.crt>
```

### Express server mTLS config
```typescript
import https from 'https';
import fs from 'fs';

const server = https.createServer({
  cert: fs.readFileSync('infra/certs/server.crt'),
  key: fs.readFileSync('infra/certs/server.key'),
  ca: fs.readFileSync('infra/certs/ca.crt'),
  requestCert: true,        // Require client cert
  rejectUnauthorized: true, // Reject if client cert is invalid
}, app);
```

## Security notes
- Rotate certificates at least annually; rotate **immediately** after any
  suspected key exposure.
- Certificates generated by the scripts are self-signed and expire per the
  chosen validity (default 10 years) — renew before expiry.
